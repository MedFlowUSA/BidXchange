# Application reliability audit — September 22, 2026

## Scope

Reviewed contractor Passport freshness, scheduled reminder behavior, pursuit decision context, assistant record retrieval and citation details, organization scoping, and existing workflow regression coverage. This is a focused code and regression audit, not a penetration test, legal review, or proof that every production workflow is complete.

## Confirmed flaws and repairs

| Priority | Finding | Repair |
| --- | --- | --- |
| High | Assistant facts could report a human-attested record as verified even when its source check was older than 90 days. | Apply UTC source-date freshness, using the recorded check date with attestation-date fallback. Expired and not-yet-effective records retain their restrictive statuses; invalid/future check dates require review. Current attestation is labeled human-attested, not independent verification. |
| High | Every assistant pursuit summary hardcoded `not_submitted`, without reading submission history. | Return `not_checked` with an explicit explanation and link to the pursuit. No absence-of-submission claim is made. |
| High | Assistant exposed a saved bid decision without testing whether its supporting context had changed. | Compare the latest scoped decision history with the existing read-only context RPC. Identify stale, current recorded review, or missing review history. Never reaffirm or mutate the decision. |

Fact search and citation-detail views now share the status policy. Retrieval selects only the source-check field from structured JSON; other private structured fields are not included. Decision reasons, context tokens and financial snapshots are not sent to the model. Assistant instructions explicitly distinguish historical decisions, current evidence and unchecked submissions.

## Validation

- New regression cases cover the 90-day boundary, stale and future check dates, invalid dates, expiration precedence, missing attestation, stale/current/absent decision history, organization scoping, structured-field exclusions and citation/search consistency.
- `npm test -- tests/ai-tools.spec.ts --workers=4`: initial targeted run passed 30 tests; additional source-projection regression added for the full run.
- `npm run build`: passed, including TypeScript.
- `npm run lint`: passed.
- `npm run test:secrets`: passed across 512 source files before this report was added.
- Hosted staging PostgREST checks accepted both new projections with a nonexistent organization filter; no customer data returned. These were schema checks, not authenticated user end-to-end model tests.
- `npm test -- --workers=4`: 208 passed, including desktop/mobile workflow regressions.

## Remaining limitations

1. The assistant still does not read actual release/submission history. The repaired answer honestly reports that limitation. Add permission-scoped release and user-recorded submission citations next.
2. Requirement text is deliberately excluded from AI retrieval pending a reviewed disclosure model. Current assistant summaries cannot provide a full clause-by-clause review.
3. The connected Apex demo and some merge/restore/outcome workflows remain incomplete in the implementation inventory. Passing existing tests does not prove those missing capabilities exist.
4. Reminders remain in-app only. The PDF guide has not yet been updated for the scheduled reminder feature.
5. Portal ingestion remains limited/manual; this release does not activate live synchronization, private uploads or outbound messages.

## Release safety

No database migrations, new dependencies, external integrations or permission changes. All reads use the existing authenticated organization-scoped client. Unknown-sensitivity evidence remains excluded. General-mode data access is unchanged. No pricing, eligibility, approval, signature or submission authority is added. Preserve unrelated local changes.
